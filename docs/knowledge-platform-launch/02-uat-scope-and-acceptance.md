# 首个内部 UAT 范围与验收

## 1. 用户和访问

- 目标用户：10–20 名内部测试者，主要是销售/商务和市场研究人员。
- 入口：邮箱登录。正式邮箱允许列表待测试人员确定后配置，不写死在代码中。
- 权限：第一阶段的已登录测试用户均可查看 UAT 数据；未登录用户不能读取业务 API 或原始数据文件。
- 禁止绕过：不得将内部 JSON、Excel、PDF 或 R2 对象作为公开静态 URL 交付给浏览器。

## 2. 导航和首批页面

左侧栏严格保持三项：

1. 首页：作为统一搜索入口，显示真实公司/报告统计、重点公司和最新报告。
2. 公司信息库：126 家公司高密度表格、组合筛选与公司详情。
3. 行业报告库：24 条可追溯元数据的搜索、组合筛选和详情；不提供伪造附件。

项目、我的工作台和管理中心不在首批业务导航中。全站搜索仅覆盖当前已加载的公司与报告元数据；服务端索引、附件全文和新闻搜索仍需通过后续产品域门禁。

## 3. 公司详情页固定顺序

各模块按以下顺序从上到下排列：

1. 原生响应式公司 Banner
2. 公司简介（HTML 展示，输出需清洗/隔离）
3. 项目分布地图与项目类型结构（桌面端同排）
4. 区域产量趋势
5. 经营与财务表现（两个财务图同排）
6. 相关新闻
7. 相关报告

渐进展示规则：只渲染已有且通过数据验证的模块；缺失数据不伪造数值，不用“0”代替未知，也不让单个模块失败使整页崩溃。如果一个预期模块的来源存在但解析失败，页面应显示可理解的局部异常状态并产生可追踪错误。

## 4. UAT 核心任务

| ID | 用户任务 | 通过标准 |
|---|---|---|
| UAT-01 | 使用邮箱进入平台 | 已授权测试用户成功进入；未登录请求不能读取公司数据 |
| UAT-02 | 从公司库找到目标公司 | 126 家档案可检索进入；8 家重点公司标识为完整 Portfolio，缺少数据的公司不被伪装为完整 |
| UAT-03 | 阅读公司详情 | 页面顺序符合第 3 节，每个值可追溯到版本化导入数据 |
| UAT-04 | 理解项目地理与类型分布 | 地图和饼图基于同一已验证项目数据集，统计口径一致 |
| UAT-05 | 查看产量和财务趋势 | 单位、币种、期间、来源和缺失值含义可理解 |
| UAT-06 | 查看相关信息 | 只显示 GitHub 中可验证的关联项；无附件的报告不显示可用下载 |
| UAT-07 | 处理部分数据与失败 | 空态、局部失败、会话失效和 API 失败均有可恢复路径 |

## 5. 工程与性能验收

- 用单元测试保护数据解析、统计口径、部分数据规则和权限边界。
- 用 API/数据库集成测试证明未登录拒绝、已登录读取、数据来源和导入幂等性。
- 用 Playwright 覆盖登录入口、三项导航、公司列表、一家完整公司、一家档案公司、报告检索和报告无附件状态。
- 本地性能基线必须分开记录冷启动/热缓存、数据量、硬件、浏览器和样本次数。目标为发现回归，不用 localhost 数据宣称企业网络 G2 或生产 G4 已通过。
- UAT 开始前必须开启请求 ID、错误日志和版本标识，否则测试反馈无法和真实故障关联。

## 6. 当前不宣称的结果

首个 UAT 不代表完整产品、完整数据、生产级权限矩阵、公司外网络性能、完整报告附件链路、服务端全文检索、生产 Cloudflare 站点或 AI 能力已交付。
